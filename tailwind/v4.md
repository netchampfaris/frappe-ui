# Tailwind CSS v4 Migration Plan (frappe-ui preset)

## Goals

- Upgrade the design-system preset to Tailwind CSS v4 while preserving all
  semantic color tokens, CSS variables, and component styles.
- Keep consumer projects (e.g. Gameplan frontend) working with minimal changes.
- Preserve the v3 preset for existing users; introduce v4 assets in parallel.
- Validate that forms and typography plugins still behave the same.

## Scope

- v3 preset: [frappe-ui/tailwind/preset.js](frappe-ui/tailwind/preset.js)
- v3 plugin: [frappe-ui/tailwind/plugin.js](frappe-ui/tailwind/plugin.js)
- Colors: [frappe-ui/tailwind/colors.js](frappe-ui/tailwind/colors.js)
- New v4 CSS-first entry (to be added under
  [frappe-ui/tailwind](frappe-ui/tailwind))
- Consumer entrypoint reference (Gameplan):
  [frontend/src/index.css](frontend/src/index.css)

## Phase 0 — Inventory & Baseline (no code changes)

- Capture current behavior:
  - Dark mode selector: `['selector', '[data-theme="dark"]']` in preset.
  - Custom theme tokens: `colors`, `borderRadius`, `boxShadow`, `fontSize`,
    `screens`.
  - CSS variables generated by `generateCSSVariables()` and injected via
    `addBase`.
  - Component styles applied via `addComponents` (e.g. `.form-input`).
- Identify all utilities that depend on custom scales (spacing, width, height,
  min/max, typography).
- Confirm which consumers import the preset (Gameplan frontend config).

## Phase 1 — Tailwind v4 Upgrade Prep

- Update dependency versions in frappe-ui only:
  - `tailwindcss` to v4
  - `@tailwindcss/forms` and `@tailwindcss/typography` to v4-compatible versions
  - Validate any PostCSS or Vite integrations for v4 defaults
- Confirm the CSS-first entrypoints and how they replace `@tailwind` directives.

## Phase 2 — CSS-First Migration (design system)

Move the design system tokens into CSS-first configuration:

- Create a new CSS entry file in frappe-ui (e.g. `frappe-ui/tailwind/v4.css`).
- Add the v4 entrypoint:
  - `@import "tailwindcss";`
- Define design tokens using `@theme`:
  - Map color palette to CSS variables for `--color-*`.
  - Map semantic colors to `--color-surface-*`, `--color-ink-*`,
    `--color-outline-*`.
  - Map spacing, radii, shadows, font sizes, and screens as needed.
- Port `generateCSSVariables()` output to `@layer base` in the CSS entry file.
- Port component styles from `addComponents` to `@layer components`.
- Keep the existing v3 preset and plugin intact; do not modify v3 files unless
  the change is strictly backwards compatible.

## Phase 3 — v4 Assets Without Breaking v3

- Keep [frappe-ui/tailwind/preset.js](frappe-ui/tailwind/preset.js) and
  [frappe-ui/tailwind/plugin.js](frappe-ui/tailwind/plugin.js) unchanged for v3.
- Add new v4 assets alongside v3 (CSS-first entry file + any v4-specific docs).
- If any shared logic is needed, add new files or exports that do not alter
  existing v3 behavior.

## Phase 4 — Consumer Wiring

- Document how consumers should import the v4 CSS-first file in their main CSS
  entrypoint (Gameplan uses [frontend/src/index.css](frontend/src/index.css)):
  - Example: `@import "frappe-ui/tailwind/v4.css";`
- Defer consumer config changes until they explicitly upgrade to v4.

## Phase 5 — Visual Parity & Regression Checks

- Validate these areas in dev:
  - Semantic color utilities: `bg-surface-*`, `text-ink-*`, `border-outline-*`.
  - Form inputs and selects (class-based styles from plugin).
  - Typography defaults for prose content.
  - Dark mode selector `[data-theme="dark"]`.
- Run representative UI pages and capture screenshots before/after.

## Phase 6 — Cleanup & Documentation

- Update any internal docs about Tailwind usage and tokens.
- Document v4-specific constraints and any changes in custom tokens.
